# mimic: 실서버 상대 재구성 + 상대 대역 봇 + v19/v18 약점 탐색

작업 디렉터리 `v18-work/zoo2/mimic/`. 마감 19:40, 시드는 개발 12000~12199 만 사용(아래 표는 전부 12000~12029 또는 12100~12107).

## 1. 실서버 리플레이 23판(real_04..26, 우리=K 옛 버전, 상대=Y) 재구성 (analyze.py, an2.py, an.json)

상대 명령은 기록에 없어서 관측(유닛 위치/수, 건물 소유, 자원)의 턴별 변화로 추정했다.

| 항목 | 결과 (23판) |

## 2. 상대 대역 봇 (전부 처음부터 작성한 C++, 공용 엔진 `core.hpp`, 변종별 main.cpp)

공용 엔진: 초반 F 몇 기 -> 나머지 자원 전부 W(ENG 있으면 W 2). 건물마다 목표를 만들고(가치=종류별 가중치, 필요 W = 1+근처 적 W) 큰 스택부터 가까운 고가치 목표에 분할 배정, 남는 W 는 가치/거리 최고 목표로 집결. 깃발은 전역 그리디 매칭으로 목표 배정, 이동 칸에 "내 W 계획 도착 수 >= 인접 적 W" 일 때만 진입. 내 건물마다 W 1기 상주, 내 깃발이 서 있는 비소유 건물(적 깃발과 대치 포함)에 지원 W, 적 깃발 사냥, TELE(역->역 5기), 습격조(t>=raidStart 에 적 진영 건물에 raidNeed 기 배정). 모든 파라미터는 환경변수 `MM_*` 로 덮어쓸 수 있다(탐색용). 턴당 평균 0.5ms, 최대 9ms(실서버 관측 160턴 재생 측정).

| 봇 | 경로 | 특징 | vs bot8 (시드 30, 60판) | vs bot_opp (20판) | vs bot15 (20판) |
|---|---|---|---|---|---|
| spread | `v18-work/zoo2/mimic/spread/bot` | 실서버 다수형 재현: F7 -> 전부 W, 건물 분산, t>=20 적 진영 건물마다 W 6기 습격조, TELE | 96.7% | 50% | 0% |
| hoard | `v18-work/zoo2/mimic/hoard/bot` | 경제 우선, W 를 쌓다가 t>=45 에 적 진영 전 건물로 12기씩 일제 공세(W 수백 기 누적형) | 96.7% | 50% | 0% |
| teleraid | `v18-work/zoo2/mimic/teleraid/bot` | 역(+60)/병원/ENG 우선, TELE 5기씩 적 역으로 보내 습격, 전진 병원 생산, t>=20 습격조 | 96.7% | 80% | 5% |
| blob | `v18-work/zoo2/mimic/blob/bot` | 한 덩어리 데스볼 시도. bot8 상대 40~60%로 기준 미달 -> 평가에서 제외(참고용) | 40~60% | 5% | - |

W 곡선 검증(v19 와 대전한 3판, 대역 spread 쪽): t10 W 37~40(실서버 상대 평균 26), t20 37~73(실서버 67), t30 30~65(실서버 85), t40 33~66(실서버 102). 초반은 실서버와 같거나 빠르고 중반 이후는 실서버 상대보다 약간 느리다.

정직한 한계: 이 대역들은 bot8 은 압도하지만 bot15/bot17 계보(둘 다 0~5%)보다는 훨씬 약하다. 즉 "실서버 상대의 대역" 이라기보다 "패턴은 같고 실력은 bot8~bot_opp 급"이다. 실서버 상대가 옛 우리 봇(bot5 이전급)을 즉시승으로 이겼다는 사실과는 모순이 없지만, 실서버 상대가 bot15 급보다 강한지는 이 도구로는 알 수 없다.

## 4. 발견한 약점 (v19)

1. **장기 소모전에서 W 경제 격차 -> 후반 전멸**: teleraid 에 진 판은 t40~60 까지 점수는 v19 가 앞서다(예 12013: t49 점수 21:10) t60~80 에 상대 W 가 79~86 vs v19 56 으로 벌어지고, t75 부근 대규모 교전에서 v19 W 56->25 로 붕괴, 이후 건물 전부 뺏기고 t140~148 즉시패(점수 0). 교전 자체는 1:1 이라 W 격차를 안 바꾼다. 격차는 생산 격차(상대는 학생회관 2개 + ENG 를 안정 점유, v19 는 자기 학생회관을 자주 뺏김)에서 나온다. 즉 v19 의 핵심 약점 = "5기 이상 습격조 / TELE 증원이 학생회관·ENG 를 노릴 때 1기 상주(threat-scaled picket)로는 못 지킨다".
2. **부하 시 시간초과**: 180판 중 1판(spread, 12018Y, 점수 앞서던 중) v19 가 몰수패. 측정 시점 컴퓨터 부하 평균 10~20(8코어에 에이전트 3개). 봇 자체 예산은 벽시계 50ms 이지만 프로세스가 스케줄되지 못하면 300ms 를 넘는다. 실서버에서 CPU 경합이 있으면 위험(재현은 못 함; 부하 탓으로 추정, 다시 측정하지 못했음).
3. 상대 모델이 v15~17 계보 전제라 비계보(대역) 상대에서 예측 정확도가 0.5~0.7 (stack/NOTES 기록과 동일). 대역이 약해 이것이 승패로 이어지진 않았다.
4. teleraid 확장 표본: 시드 12030~12079(100판) v19 100승 0패. 시드 12000~12079 합계 v19 vs teleraid = 155승 5패(96.9%). 패배는 전부 앞 30 시드 중 12002·12013·12028·12029 에 집중 -> 약점은 맵(시드) 의존적이고 드물다(80시드 중 4시드).
5. 응답 시간(부하 시): 실서버 관측 160턴을 먹여 측정(컴퓨터 부하평균 13~25): v19 real_19 입력 평균 16ms/p95 30ms/최대 42ms, real_04 입력 평균 27ms/p95 63ms/**최대 254ms**(300ms 제한에 근접). v18 은 평균 1~1.4ms/최대 21ms. 부하가 없으면 v19 최대 ~25ms(STATE 기록)이므로 254ms 는 스케줄링 지연으로 추정되나, 실서버가 코어를 공유하면 v19 는 몰수패 위험이 있고 v18 은 사실상 없다. 재측정(부하평균 ~12, real_04~15 12개 리플레이 977턴): 평균 8.6ms, p99 24.7ms, 최대 34.8ms, 100ms 초과 0턴 -> 254ms 는 부하평균 ~25 때의 일시적 지연이었다. 개선안: 벽시계 예산 50ms -> 25~30ms 로 줄이거나 턴 시작 후 경과시간 기반 즉시 중단 강화.
6. 맵 의존: v19 가 지는 시드는 12002/12013/12028/12029(+v18 은 12007). 개발 시드에서 v19 가 자주 지는 맵 유형 파악 필요(미분석).

## 5. 무작위 탐색과 패치 시도

* `search.py`: spread 엔진의 파라미터 17개(깃발 수, 가중치, 습격 시점/인원, TELE, 상주, ...)를 무작위로 뽑아 v19 승률이 낮은 설정을 찾음. 12100~12107 시드 8개 x 17설정: v19 승률 93.8%(1설정)~100%. v19 를 특별히 약하게 만드는 파라미터 조합은 못 찾음 (탐색 중단).
* `patch/`: v19 소스 복사 + `-DTUNE` 빌드(`bot_tune`, 환경변수 `P<n>` 로 v19 자체 파라미터 조정: P94/P95 = 위협 비례 피켓 크기/상한, P64 = 피켓 건물 수, P63 = 상주 추가 수, P66 = 피켓 최소 W). teleraid 를 상대로 시드 12000~12029 60판 측정. 기준(파라미터 기본) 54/60=90% (바닥이 매판 결정적이지 않아 91.7% 와 다름).
  결과는 아래 6절 표. 표본 오차(SE 약 4%p)보다 큰 개선은 없다 -> **패치 채택 기준 미충족, 채택하지 않음**.

## 6. 패치 후보 측정 (teleraid, 시드 12000~12029, 60판)

| 설정 (v19 TUNE 빌드, 환경변수) | v19 승률 (teleraid 60판) | 비고 |
|---|---|---|
| 기본(변경 없음) | 54/60 = 90.0% | 기준 |
| P94=100 P95=8 (위협 비례 피켓 2배, 상한 8) | 55/60 = 91.7% | |
| P64=7 (피켓 건물 5->7) | 54/60 = 90.0% | |
| P94=100 P95=8 P64=7 | 측정 실패(아레나 출력 없음, 부하 추정) | 재측정 못 함 |
| P63=2 (상주 추가 +2) | 51/60 = 85.0% (errors=2) | 기준보다 나쁨(부하 오류 2판 포함) |
| P66=6 P94=100 (피켓 최소 W 6, 스케일 2배) | 54/60 = 90.0% (forfeits=2) | 몰수 2판(부하) |
| P64=8 P63=3 P94=100 P95=8 | 55/60 = 91.7% | |

전부 기준선의 표본오차(SE 약 4%p) 안이다. 기존 v19 손잡이(피켓 크기/개수/상주)를 키우는 것으로는 teleraid 약점이 안 고쳐진다 -> 구조적 변경(학생회관/ENG 전용 다인 방어 예비대 또는 TELE 증원 대응, 교전 후 생산 격차 회복)이 필요하며 이 시간 안에 구현·평가하지 못했다. **패치 미채택.** `patch/` 는 v19 소스 복사 + TUNE 빌드일 뿐이며 제출용이 아니다.
