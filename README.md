## 게임 한눈에 보기

두 팀이 동시에 명령을 내리는 턴제 전략 게임입니다. 병력은 깃발병(점령), 전투병(전투), 정찰병(두 칸 이동·점수 공개) 세 종류이고 생산 비용은 각각 5, 3, 2입니다.

- **건물 17개**: 중앙광장(항상 3점) + 점대칭 16개. 학생회관은 수입, 도서관은 점령 할인, 공학관은 전투병 생산 할인, 병원은 추가 생산 거점, 역은 순간이동, 방송국은 점수 공개, 보급소는 최초 점령 보너스를 줍니다.
- **점령은 깃발병만**, **전투는 전투병만** 하며 전투병은 같은 수만큼 상쇄합니다.
- **승부 판정**: 상대 점수가 0이고 내 점수가 맵 총점의 과반이면 즉시 승리. 종료 시에는 점수 → 누적 점령 점수-턴 → 생존 병력 환산 순으로 비교합니다.
- 자세한 규칙은 `yk-development-tools/docs/rulebook.md`, 운영 사항은 `yk-development-tools/docs/PLATFORM_OPERATIONS.md`

## 에이전트 구조

```
main.cpp        입출력 루프, 턴 시간 관리, 예외·입력 오류에도 항상 유효한 응답
protocol.hpp    서버 프로토콜 파서
sim.hpp         게임 엔진 턴 처리를 그대로 옮긴 시뮬레이터 (탐색용 롤아웃)
policy.hpp      위험 가중 경로, 목표 배정, 점령 비용 예약, 생산 결정 + 파라미터 표
search.hpp      후보 계획을 시뮬레이터로 롤아웃해 고르는 국소 탐색 + 상대 모델 선택
ordsort.hpp     libc++ std::sort 포팅 → 표준 라이브러리가 달라도 동점 정렬 결과가 같음
```

- **정책**이 후보 계획을 만들고, **탐색**이 시뮬레이터로 굴려 가장 좋은 조합을 고릅니다.
- 상대는 여러 행동 모델 중 지금까지 **예측이 가장 잘 맞은 모델**로 가정합니다. 서버에서는 이 예측 정확도가 평균 0.07로 매우 낮아서, 예측이 틀려도 안전한 결정(깃발 안전 보정, 상대 최선 반격 손실 평가)을 따로 넣었습니다.
- 한 턴 탐색은 50ms로 제한하며, 서버는 로컬보다 약 7배 느려 **계산량이 곧 서버 강도**입니다 (실서버 평균 응답 약 28ms).

## 성능

모든 비교는 **서버속도 모의**(서버 응답 시간에 맞춰 봇의 CPU 시간을 제한한 조건)에서 새 시드로 측정했습니다.

| 비교 | 결과 |
|---|---|
| v22 vs v20 | 88.8% |
| v28 vs v27 | 68.0% (200판) |
| v36 vs v35 | 73.2% (300판) |
| v50 vs v28 | 84.3% (200판) |
| 합성 상대 4종 664판, v28 → v50 | 361승 → 537승 |

**실서버(우리 팀 경기)**

| 버전 | 전적 | 리더보드 순위 |
|---|---|---|
| v20 | 15승 9패 | 10위 |
| v27 | 7승 5패 | 20위 |
| v28 | 13승 11패 | 27위 |
| v50 | 13승 11패 | **15위** |

승률은 54~63%로 거의 일정했지만 순위는 올랐습니다. 순위가 비슷한 팀끼리 붙는 스위스식 대진으로 보여, 진전은 승률이 아니라 **순위**로 나타났습니다.

> ⚠️ 합성 상대는 우리 봇 계열의 변형이라 모의 결과가 실서버에 그대로 오르지는 않습니다. v51은 v50 대비 합성 상대 모의에서 이득이 재현된 쪽(상위권 팀 모사 상대 +40판 안팎, 나머지는 중립)을 선택했지만, 실서버 성적은 이 문서 작성 시점에 확인하지 못했습니다.

## 실행하기

```bash
# 빌드 (C++20, 표준 라이브러리만)
clang++ -std=c++20 -O2 -o bot51 yjc-submission51-cpp/main.cpp

# 한 판 붙기
python3 yk-development-tools/bots/dist/starter/play_local.py --bot ./bot51 --opponent ./bot50 --seed 1

# 여러 판 벤치마크 (진영 번갈아 배치)
python3 benchmark.py --botA ./bot51 --botB ./bot50 --games 100
```

로컬 속도 결과는 서버보다 계산이 넉넉한 조건이라, 계산이 무거운 봇일수록 서버에서 약해질 수 있다는 점에 유의하세요.

## 개발에서 배운 것

- **로컬에서 강한 것과 서버에서 강한 것은 다르다.** 서버가 약 7배 느리다는 관측에서 출발해 서버속도 모의를 만든 뒤에야 개선의 의미를 판단할 수 있었습니다.
- **잡음을 정직하게 다뤘다.** 같은 봇도 120판 중 약 40판이 바뀌어서 같은 시간대 짝지은 비교, 새 시드 재검증, 선택 편향 점검 없이는 작은 차이를 채택하지 않았습니다.
- **상위 팀의 공통 강점은 경제 건물(특히 공학관)의 지속 보유**였습니다. 이를 완전히 따라 하지는 못했고, 초반 주력 배치 변경은 다음 과제로 남았습니다.
